# 구현 및 검증 보고서

## 산출물

요청한 모노레포 구조에 React Native 모바일 화면 11개, 기기 저장, FastAPI 상담 API, 판례 수집/전처리/벡터 검색, 선택적 Ollama RAG 연결을 구현했습니다. 로컬 데모와 HTTP 서버 모드를 구분합니다.

|앱 도메인 테스트|4개 통과|

앱 테스트: 잘못된 날짜·미래 날짜·음수 금액 차단, 완료 사건의 이어 상담 시 ID·상태·기록 유지, 저장 옵션에 따른 결과/자료 제외, 필수 동의·비밀번호 확인.

서버 테스트: 기본 API/질문, 입력 오류에 원문 미반환, DB 미구축 상태, 기타 검색 제외, 동일 분야 TF-IDF 검색, AI의 알 수 없는 인용 ID 거부, 미검토 행 및 판결 전문 필드 제거.

## 미검증 및 제한

- Android/iOS **실기기·에뮬레이터 실행은 미검증**입니다. 번들 생성은 네이티브 바이너리 빌드/설치 테스트가 아닙니다.
- 브라우저 기반 보조 미리보기도 이 환경의 로컬 접속 경로가 404를 반환해 시각 검증하지 못했습니다.
- 법제처 API 인증값이 없어 실제 수집 요청은 실행하지 않았습니다. 공식 XML 스키마 기준 구현입니다.
- Ollama 모델을 실행하지 않았습니다. 어댑터의 JSON/인용 검증은 모의 응답으로 테스트했습니다.
- SDK 호환 검사는 로컬 Expo 호환표 기준이며 React Native Directory 원격 검사와 Expo Go 실기기 실행을 대체하지 않습니다.
- 계정 인증, 증거 원본 업로드, 사용자별 사건 서버 저장, 푸시 알림은 미구현입니다.
- 법률 정확성, 검색 재현율, 생성 답변 품질, 동시 사용자 부하 및 운영 보안은 검증하지 않았습니다.

## 휴대폰에서 확인할 순서

1. 홈 → 분야 → 상황 입력. 날짜 형식 오류·빈 내용의 검증 확인.
2. 질문의 선택/직접 입력/이전/건너뛰기 확인.
3. 결과 → 체크리스트 → 저장 → 내 사건에서 기록 확인.
4. 앱 재시작 후 사건/작성 중인 입력 복원 확인.
5. 상세에서 완료 처리·메모 수정·이어 상담 후 상태 유지 확인.
6. 파일 선택/취소, 10MB 제한, 5개 제한, 목록 삭제 확인.
7. 회원가입 입력 검증·로그인·로그아웃·전체 데이터 삭제 확인.
8. 폰트 확대, 키보드 표시, 하단 안전 영역, Android 뒤로가기 확인.
9. API 모드로 전환 후 정상 응답/서버 중단/재시도 확인.
10. 실제 검토된 판례 색인과 모델 준비 후 출처·요약 원문 대조.
